Project:

	Collaborative Research: Separating transient and enduring forms of
	change in adult attachment styles


Investigators:

	R. Chris Fraley
	Omri Gillath
	Pascal Deboeck


Research Goal:

	The primary objectives of this research are to better understand continuity and change in 
	attachment styles, and, specifically, the extent to which various life events lead
	to enduring vs. transient changes in attachment.

Method:

	Participants completed a survey on attachment, personality, and
	life events once a month for up to 24 months total. This design allows us to map
	continuity and change BEFORE specific events take place as well as AFTER those
	events take place. 


Data:

	Data are stored in several deidentified objects/files. With few exceptions, the variable labels 
	described below should be similar across the long vs. wide files, although the wave suffix 
	is omitted from	variable names in the long forms.

	Core/Full Data

		  The core data files represent all the data to date (as of the most recent backup). These
		  should be treated as archival files. (Data analytic files are the "explore" and
		  "confirm" files described below.)

		  data2wide.txt 
			
			Person by variable matrix. All longitudinal/repeated-measures assessments are 
			represented in columns labeled with suffix _XX for assessment wave (01 - 24)

			Format: Tab-delimited text file. NA for missing values.

		  data2long.txt
			
			Longform version of the data. Each row represents an assessment wave
			for a given person. Waves are nested within persons. Each person
			has 24 rows, even if the person hasn't completed 24 assessments.
			Between-persons non-repeated measures (see below) are simply copied
			across the 24 waves. A variable/col named 'time' appears first that
			simply indexes the rows for each person. "user_id" represents the 
			unique ID number associated with each person (observations/rows are
			nested within person).

			Format: Tab-delimited text file. NA for missing values.

	Exploratory and Confirmatory Data Subsets

		  The full data files are further split into exploratory and confirmatory subsets.
		  This is done for two reasons. First, for the purposes of registering data-analytic plans
		  and scripts, it will be helpful to have an exploratory/test sample to ensure that the 
		  code is working appropriately before full analyses are conducted. Second, because
		  the data set is complex and involves multiple measurements, there are many potential questions
		  that can be addressed. Doing so with an exploratory sample allows investigators to examine
		  the data for any number of purposes. Anything uncovered in such explorations that investigators
		  wish to pursue further should then be registered and evaluated independently 
		  in the cross-validation/hold-out/confirmatory sample.

		  I thought it would be best to demarcate these subsets a priori, before data collection is complete. 
		  The exploratory sample was created by sampling 300 cases at random from the first 2000 cases. 
		  The randomization seed was set to the NSF grant number for reproducibility purposes 
		  (set.seed(1423874)). The exploratory, both wide and long form, samples are based on 
		  these 300 cases; the confirmatory samples (wide and long) are based on the remaining cases. 
		  
		  The contents of these data sets will evolve in the backup folder as cases
		  are added and people continue to participate in longitudinal followups. Nonetheless,
		  the specific cases/people to be included in each subsample is *fixed* before data collection
		  is completed.


		  explore2wide.txt and confirm2wide.txt
			
			Person by variable matrix. All longitudinal/repeated-measures assessments are 
			represented in columns labeled with suffix _XX for assessment wave (01 - 24).
			For exploratory (explore) or confirmatory analyses (confirm).

			Format: Tab-delimited text file. NA for missing values.

		  explore2long.txt and confirm2long.txt
			
			Longform version of the data. Each row represents an assessment wave
			for a given person. Waves are nested within persons. Each person
			has 24 rows, even if the person hasn't completed 24 assessments.
			Between-persons non-repeated measures (see below) are simply copied
			across the 24 waves. A variable/col named 'time' appears first that
			simply indexes the rows for each person. "user_id" represents the 
			unique ID number associated with each person (observations/rows are
			nested within person).
			
			For exploratory (explore) or confirmatory analyses (confirm).

			Format: Tab-delimited text file. NA for missing values.

"time" (long form files only)

	A simple index, starting at 0 and ending at 23, that represents the assessment
	wave for the person in question. Each person has 24 rows regardless of whether
	the person completed 24 assessments.

"user_id"               

	This is the identification number used to link a person's data across multiple SQL databases
	during data collection. Each participant has a unique user_id. The number itself has
	no intrinsic meaning.


"registration_date"     

	Date the user account was created (i.e., when the user activated the account by submitting
	an email address). This date may or may not be the same as submission_date below because
	the user might not have completed the survey on the same day that the account was created
	(e.g., perhaps the registration email didn't arrive in a timely fashion).


"sex"                   

	"Are you male or female?" 

		0 = female
		1 = male
		NA = no response


"birthyear" or "age" (depending on the file)    

	"In what year were you born? "

	Option selected from pull-down menu, ranging from 1915 to 2007

	Internal reminder: In original SQL file, this is called 'age'. 


"country"     

	"What is your country of residence?"

	Pull-down menu. Most salient options (at top of list, outside of
	alphabetical listing but also listed in ABC list) are "United States," 
	"Canada", "United Kingdom", and "China". 
	
	All participants in the paid sample are from the United States; this 'variable' should not 
	actually vary.


"ethnicity"

	"How would you describe your ethnicity? "

	Answers are free responses and will need to be coded to be used meaningfully.


"wave"

	Current Assessment Wave

	This records which assessment wave the respondent will be completing the next time
	he or she logs in. The total number of assessments a person *has* completed
	is 1 minus this value.


"age2"     

	An estimate of the user age.

	This is an internal calculation based on subtracting users' birthyears from
	the registration dates. It is an imperfect estimate because we are only 
	attending to birth years and not birth months (which were not recorded).



"social_network2"
"mastery2"
"resilience2"
"cog_flex2"

	Cognitive, Social, and Psychological Resources

	These are composites based on items Omri included in the assessments. 
	The full survey was administed occasionally, and, as such, there may
	be repeated measures for some people (see below). But these measures
	were included largely as a way to examine how various factors might
	predict the direction and magnitude of change over time in other constructs.
	Thus, they are included here as between-persons variables. The compilation script
	extracts the scores from the FIRST administration of the survey for the purposes
	of creating these between-persons (level 2) variables.

	social_network2
		
		A composite based on the number of social relations people report.
		Example item:
		How many family members or relatives can you talk to about things personal to you?
		Each item rated on a 0 to 9 scale.

	mastery2 

		The Sense of Mastery Scale (Dalgard et al., 2007). 
		Example items:
		"I have little control over the things that happen to me. " 
		"Sometimes I feel that I'm pushed around in life. "
		Each item rated on a 1 (strongly disagree) to 5 (strongly agree) scale.
				
	
	resilience2

		Brief Resilience Scale (Sinclair, V. G., & Wallston, K. A. (2004)
		Example items:
		"I tend to bounce back quickly after hard times" 
		"I have a hard time making it through stressful events"   
		Each item rated on a 1 (strongly disagree) to 5 (strongly agree) scale.

	cog_flex2

		Cognitive Flexibility Scale (Martin & Rubin, 1995) 
		Example items:
		"I avoid new and unusual situations. "
		"I seldom have choices when deciding how to behave. "
		"I am willing to listen and consider alternatives for handling a problem. "
		Each item rated on a 1 (strongly disagree) to 5 (strongly agree) scale.

BACKGROUND INFORMATION ABOUT PARTICIPANTS
Repeated Measures
===================================================================================


The following set of variables come from the Background Information section of the survey.
When a user has registered and completes his or her first survey, the user is immediately
directed to a Background Information section that asks basic demographic questions.

The answers to these questions can be changed at any time (i.e., at repeated assessments)
by navigating to the Background Information section and updating the answers. Moreover,
users are often prompted to do so explictly when certain life events are reported that seem
relevant (e.g., losing a job, breaking up). 

The responses here are stored as separate waves, using the variable naming convention
of variable_01 - variable_24 for waves 1 through 24. The existing info is simply copied
across assessments unless it was manually changed by the user. Given that many of these
variables are unlikely to change (but CAN change) it might be best to 
regard these as between-person variables and use the first assessment (i.e., 
variable_01) for most analytic purposes. But, if one is interested in their change, 
the repeated-wave data are available here.

"anxietyc_01" - "anxietyc_24"    
"anxietyd_01" - "anxietyd_24" 


	Experiences in Close Relationships - Relationships Structures (ECR-RS)
	Attachment Styles

	Fraley, R. C., Heffernan, M. E., Vicary, A. M., & Brumbaugh, C. C. (2011). The Experiences 
	in Close Relationships-Relationship Structures questionnaire: A method for 
	assessing attachment orientations across relationships. 
	Psychological Assessment, 23, 615-625.


	The following sets of variables represent people's attachment avoidance (avoid)
	and attachment anxiety (anxiety) scores across five relationship domains:

	e = general
	a = mother
	b = father
	c = romantic partner
	d = best friend

	Thus, avoide, for example, is avoidance in general and anxietyc is attachment
	anxiety with romantic partners. The numeric suffix represents the assessment
	wave (01 - 24) in the wide files. All composites should be on a 1 (low) to 
	5 (high) scale.



	Procedural notes: 
	
	For the general items, which appeared first, the following instructions were used:
	"Please read each of the following statements and rate the extent to 
	which you believe each statement best describes your feelings 
	about <B>close relationships in general</B>."

	For the relationship-specific questions, people were giving the following instructions: 
	"Please rate the extent to which you agree or disagree with these items with 
	respect to <TARGET>" where TARGET was mother, father, partner, or best friend.

	If people reported being in a romantic relationship, 
	we asked them to rate the items with respect to their partner. If the person was not
	in a relationship, we asked them to reflect on how they think they would feel
	in a relationship (see below).

		"You indicated previously that you are not involved in a romantic (dating/marital) relationship. 
		If that is still correct, <I>please imagine</I> how you think you would feel and behave 
		in a romantic relationship. If you are currently involved in a relationship that you 
		were not involved in previously, please rate how you feel with respect to that individual."

	If a parent is not alive (demographics), the ECR-RS items are not administered 
	for that parent. Thus, a person will have missing data for avoida and anxietya if that
	person's mother was not living.

	State Adult Attachment Measure (SAAM)

	Gillath, O., Hart, J., Noftle, E. E., & Stockdale, G. D. (2009). Development and 
	validation of a state adult attachment measure (SAAM). Journal of 
	Research in Personality, 43, 362-373.

	Assesses the extent to which people currently (at the time of the assessment)
	feel anxious (saam_anx), avoidant (saam_avo), or secure (saam_sec) with 
	respect to attachment. The composites are based on an abbreviated version of the 
	full SAAM scale, using 3 items per scale.

	Instructions
	"The following statements concern how you feel <B>right now</B>. 
	Please respond to each statement by indicating how much you agree or disagree 
	with it as it reflects your <B>current</B> feelings. Please 
	select the response that best indicates how you feel at the 
	moment. 
	
	Item stem: "Right now . . ."

	Items used: 
	"I feel loved","I feel like I have someone to rely on","
	I feel secure and close to other people","I really need someone's emotional support",
	"I really want to feel loved right now","I want to share my feelings with someone",
	"If someone tried to get close to me, I would try to keep my distance",
	"I feel like I am loved by others but I really don't care ",
	"I'm afraid someone will want to get too close to me"

	Life Event Followup Questions

	If the respondent indicated that a life event had taken place since the last assessment, the
	respondent was asked additional questions about the event.

	Those responses are represented as follows: eventXXa_YY, eventXXb_YY, eventXXc_YY,
	where XX is the identifier for the event (see above) such that event20 refers to
	"I took a vacation or went on holiday" and YY refers to the assessment wave (01 - 24).

	The a, b, and c in the variable labels refer to responses to the following questions 
	for the event in question:

	a = "This was a positive and rewarding experience." (1 = Strongly Disagree to 5 = Strongly Agree)
	b = "This was a stressful experience."  (1 = Strongly Disagree to 5 = Strongly Agree)
	c = "Approximately how many days ago did this take place?" (pull down menu ranging from 0 to 
	"more than 40 days ago". These responses are coded numerically, ranging from 0 to 40.

	Example: event07b_04 refers to respondents' ratings of the stressfulness (b) of receiving 
	a work-related promotion (event07) at assessment wave 4 (_04). 

	Most of these variables are NA (missing) because the questions are only asked about the event
	if the person indicated that the event had taken place. Responses DO NOT default to 0 for these
	specific items (in contast to the binary "did the event take place or not" items above).


	People were also given the opportunity to write about these life events using a textbox/textarea. 
	I have not included those data here because some of those data 
	could be used to identify participants, depending on what they wrote.

	Fraley, R. C., & Davis, K. E. (1997). Attachment formation and transfer in young adults'

	Instructions

	YY refers to the assessment wave (01-24). The WHOTO was not consistently administered
	until 2017, thus there will be fewer data for this measure than for others.

	WHOTO questions, corresponding to whotoXX (01-06)

	01. Who is the person you most like to spend time with?
	02. Who is the person you don't like to be away from?
	03. Who is the person you want to be with when you are feeling upset or down?

	Response options for each question. Only one can be selected.

	<OPTION VALUE = 'mother' >mother</OPTION>

	WHOTO numeric scores

	These scores are measurements of the extent to which a person (e.g., mother) is used as
	an attachment figure. The higher the score, the more attachment functions the person serves.


	These are scores computed from the WHOTO nomination data. In short, each potential target person
	(e.g., mother, father, partner) receives a point each time he or she is nominated
	for whoto01-whoto06. Thus, a person who nominates mother for each of the six whoto items
	would receive a score of 6 for whoto_mother. A person who nominated mother for two of those
	items and father for the other four would receive a score of 2 for whoto_mother and
	a score of 4 for whoto_father. 

	Because people were only allowed to nominate one person for each of the six WHOTO items,
	the scores are necessarily negatively correlated (i.e., the more times mother is nominated,
	the fewer times someone else can be nominated.)

	Submission Date (Days since 2014-01-01)

	This is a recoding of the previous information (i.e., submission_date_YY) to facilitate quantitative 
	analyses. Each date is recoded (using only date information and not time information) to represent the

	Note: The built-in R function uses 1970 as the origin. To minimize the spread of numbers, I further
	adjusted the values for 2014-01-01. We will prob need to transform this further to make the range
	of values less wide (see below).


"daysfromstart_01" - "daysfromstart_24" (wide form)

	Submission Date (Within Person - Initial assessment as 0)

	This representation of time codes the number of days that have elapsed since the person's
	initial assessment. (It is computed as the difference between the date at wave k and wave 1. Thus,
	the initial wave is coded as 0 because it is 0 days from itself.) For many purposes, this representation
	of time will be most appropriate for within-person analyses or as a base for other computations.
	However, it might require rescaling for analysis purposes because the range will be exceptionally 
	large compared to many of the other measurements (which are often on 1 to 5 scales). (see below)

"rlength_01" - "rlength_24"

	Relationship Length

	This is allowed to vary within-persons simply because people have the opportunity to 
	end and start new relationships. Otherwise, it should vary almost perfectly with some index of time.

	This variable is computed internally. Participants were asked what year and month
	their relationship had started. (These are stored in the server mySQL database as 
	rlengthyears and rlengthmonths).
	
	From that information, a YYYY-MM date is created for the start of the relationship. That date
	is then subtracted from the date of submission for the wave in question. The result
	is a value that represents the number of DAYS that has transpired since the start of the
	relationship and the date the assessment was completed. (If one wishes, this value can be divided by
	365 to put it in a year-based metric rather than a day-based metric.)

	Note: Some (a handful) of the values are negative simply due to approximations and incomplete information. 
	For example, if someone did not record the month the relationship started and only the year, the month was
	set to Jan/01 for the purposes of the calculations. 










"eventba01" - "eventba25"

	Before/After or Pre/Post Event Information
	
	Only exists in the long version of the files. Separate variable for each of the 25 events. 
	Represents whether the assessment wave in question occurred prior to or after the onset of an 
	event (e.g., job loss). If the event never occurs, the person will have a 0 for each wave.
	Once the event has occurred, the person will get a 1 for that wave and all waves that follow.
	If the event took place in the 30-days before the initial survey, the person will have 1's for
	every wave. This coding system is designed to partition time into "before and after" periods for
	each event, even if the event can, in theory, occur more than once.

timec01 - timec25  

	Time Centered on Event 
	(long stacked version only; created separately for expore and confirm samples; not in core file)

	A within-person version of time that is centered on the first occurance of an event. The different
	variables (i.e., 01 - 25) represent each of the 25 assessed events.
	
	timec01, for example, represents a version of time for each person where 0 is the wave
	for the event in question and negative values are before and positive values are after. 
	If the event did not happen for the person, this is missing. In metric of years, thus a
	value of 1 means "assessment wave 1 year since the onset of the event." If the event never 
	occurred for a person, missing values.

timec01_square - timec25_square  (long stacked version only)

	Time Centered on Event (Squared)
	(long stacked version only; created separately for expore and confirm samples; not in core file)

	Same as above, but squared values in case quadratics need to be examined.

aveba01 - aveba25  (long stacked version only)

	Average Number of Occasions in Post-Event Phase
	(long stacked version only; not in core file)

	This represents, for each event (01 - 25), the average value of the before-after code for that person.
	Thus, if a person got ill early in the study, the person will have a lot of 1's for 
	eventba01 compared to someone who got ill near the end of the study. This is a between-persons or 
	level 2 variable that can be used to control between-person differences in mean levels of eventba01 (or 
	any other event) in analyses that examine within-person effects of eventba.

	Note: This should be centered within any sample in which is it used so that the zero point is meaningful.
		
aveevent01 - aveevent25  (long stacked version only)

	Average Number of Events 
	(long stacked version only; not in core file)

	This represents, for each event (01 - 25), the average number of such events the person experienced.
	Thus, if a person got ill often, he or she will have a larger value for aveevent01 than someone
	who got ill less often. This is a level 2 or between-person variable for each event.

	Note: This should be centered within any sample in which is it used so that the zero point is meaningful.
